# CONTRIBUTING

Thank you for your interest in contributing to the DAB Control Suite.

## Development Workflow

Every change follows the same workflow:

1. Analyse the existing implementation.
2. Identify all affected files.
3. Create a short implementation plan.
4. Implement only the required changes.
5. Verify syntax and runtime behaviour.
6. Document the performed checks.

## Coding Rules

- Keep changes focused.
- Do not duplicate business logic.
- Use descriptive commit messages.
- Preserve backward compatibility whenever possible.
- Keep REST APIs consistent.

## Pull Requests

Please include:

- A short description
- Motivation
- Files changed
- Validation steps
- Screenshots (if UI changes)

## Bug Reports

Include:

- Operating system
- DAB Control Suite version
- Hardware
- Steps to reproduce
- Expected behaviour
- Actual behaviour
- Relevant log excerpts

## Feature Requests

Describe:

- Problem
- Proposed solution
- Possible alternatives

## Project Philosophy

The DAB Control Suite follows a simple engineering principle:

> Analyse first. Verify second. Implement third.

Architectural decisions should always be preferred over quick fixes.
